# 🐾 喵喵粮仓 (Meow Pantry) · 纯本地猫咪囤货与喂养管家

专为养猫家庭打造的纯本地离线 PWA 应用（适配 iOS Safari / Android Chrome 主屏幕安装），部署于 GitHub Pages（如 `yoyogipark/meow-pantry`）。零后端、零云数据库、零账号登录，100% 数据保存在手机本地（`IndexedDB` + `LocalStorage` 双引擎时间戳校验同步）。

## ✨ 核心功能特性

1. **四大核心模块**：
   - **粮仓库存**：支持猫粮、湿粮、冻干、零食、营养品、药品和日用品 7 大分类；支持生产日期 + 保质期 ↔ 过期日期双向自动互推（含闰年与大小月末安全钳制）；支持整件拆封倒计时、一罐分多顿（1/2、1/3、1/4、吃完剩余）余量追踪、状态与属性子筛选及详细/极简双视图。
   - **每日记录**：支持早饭、午饭、晚饭、加餐/零食、用药/护理记录；内置「已拆封常喂口粮一键快捷点选」与「上次投喂份量自动记忆」；支持一键复制前一天日常饮食（自动跳过低频驱虫药）、删除记录同步撤回罐头/库存余量，以及室内猫低频驱虫提醒（30/60/90/180/365 天）。
   - **喂养分析**：区分 **普通食品（猫粮/湿粮/冻干/零食）**、**营养品**、**药品护理**和**日用品**的库存总值；提供近 30 天饮食占比、适口性/耐受度档案与「近期优先投喂建议」，日用品不参与投喂分析；支持分类或健康度标签联动筛选粮仓库存。
   - **备份设置**：支持人民币（CN¥）/ 日元（円）双币种独立核算与百克单价换算；提供 **库存操作历史流水账**（入库、复购、拆封、分顿投喂、核销、过期丢弃、撤回退库、手动调整全记录）及 JSON 完整备份恢复（全面兼容 v1/v2/v3/v4 备份结构，可选择智能合并或全量覆盖，覆盖前自动保存本地快照并可撤回）。

示例库存（包括日用品）及其关联流水不计入消耗预测；清空示例也会移除关联的示例记录和流水。智能合并产生的新数据需要重新导出 JSON 备份。

粮仓极简视图展示批次摘要，适口性可在批次详情查看；点击行可查看详细信息和操作。左滑可快捷记录喂食或用药，已开封日用品可快捷核销，键盘可用左方向键展开操作。极简模式默认每页 20 条，并与详细模式分别记住每页数量。按先到期排序时，批次按现有状态优先级排列；状态颜色沿用日期状态判断。极简进度条表示开封保鲜期已消耗比例，与详细卡片的剩余比例互补；未开封或缺少可计算的保鲜期时不显示，已开封且过期的批次显示满格。

库存详细、极简视图及批次详情的规格统一使用 g、kg、mL、L 显示重量和容量；可确定与净含量重复的规格不重复显示，不改变原始数据。极简视图中未填写过期日期的日用品不显示过期日期提示，开封保鲜期仍正常显示。

营养品和药品的净含量可选择克或毫升，毫升不会自动换算为克。旧商品已保存的克数保持不变，如原本应为毫升，请编辑并重新确认规格。

喂养分析中的过期库存可直接丢弃：开封件按实际开封件处理，未开封件可选择数量，共用密封包装需整盒处理。丢弃记入库存流水和累计核销，不生成喂食记录，也不参与消耗预测；包含丢弃的批次不计入平均使用时长。

商品可按分类选择形态：冻干（主食、零食、粉末）、湿粮（罐头、餐盒、餐包）、零食（猫条、肉干、饼干、洁齿、奶制品、其他）、营养品（粉剂、膏剂、液体、片剂、胶囊）、药品（片剂、胶囊、膏剂、滴剂/液体、自定义）和日用品（猫砂、清洁用品、一次性用品、配件耗材）；猫粮无需选择形态。旧形态和旧包装单位保留为历史值，不会自动重新分类或更改数量。组合包装按内包装件数计库存，内外包装单位不能相同；新猫条按支入库，旧盒装猫条仍可编辑原有换算。

零食冻干、冻干粉末和营养粉可直接选填每件所含块数或勺数。药品滴剂/液体需选择滴或毫升，其他需要换算的形态可在折叠区选填；未填写有效换算时可记录份量，但不会按该单位扣库存。同单位直接按件计算。营养品不提供预设用量；药品快捷用量和提醒间隔仅方便录入，不代表推荐剂量或用药周期，请遵循兽医指导。

支装零食的喂食快捷项为半支、1支、2支；选择口味后默认填写1支，已有开封余量时优先填写该余量。余量提示展示当前单支剩余量、对应克数与百分比，不重复口味总库存。今天的默认份量可换算且库存足够时同步开启扣减，补录历史日期仍需手动确认。超过所选口味可用量或当前扣减规则的快捷项不可选，输入异常会就地提示；填写每支净含量后仍可输入克数换算。喂食弹窗不提供单独核销入口，保存喂食时可同步扣减库存。

护理记录支持一次多选护理项目，并可设置统一的下次提醒；多选时展示各所选项目中最短的建议间隔，提醒仍可自行修改或关闭。

喂食和用药记录的评价可通过胶囊选择或再次点击取消；备注按需展开，已有备注会自动显示。

食品、营养品和药品可在“更多信息”中多选功效标签，也可添加自定义标签；标签用于记录商品信息，不代表功效或用药建议。旧“包装补充”会复制到备注，原值保留以兼容旧分组和规格换算。日用品继续使用“款式补充”。

喂食记录中，「记录未入库商品」用于填写有品牌和品名、但未录入仓库的商品；「记录自制 / 无品牌食物」只需填写食物名称和份量，无需品牌，默认归入湿粮，也可自行调整品类。两种方式都不会创建或扣减库存商品。

商品批次面板原位展开，不遮挡下方表单；仅列出在库批次，支持按品牌、商品、口味或规格搜索，列表和手动入口分开。选中项和列表统一为缩略图与两行文字，开封、临期和过期状态用徽标区分；规格等补充信息保留在完整提示和搜索中，不额外占行。新增喂食优先选择最近使用的在库批次；已核销批次不再提供为选项，但既有记录的批次引用保持不变。多口味商品须选择实际口味；湿粮快捷份量按1/4、1/3、半件、1件排列。普通食品按当前时间推荐餐次，21:00至次日05:00推荐夜宵，零食与冻干仍默认加餐；日出、餐具、月亮图标分别代表早上、晚上、夜宵。手动选定餐次后切换商品不会覆盖该选择，历史记录的餐次保持不变。

日用品主要管理猫砂、湿巾等消耗品，录入时需要填写每份规格；效期与开封保鲜期可选。同款分组会换算等价重量或容量（如 6 升与 6000 毫升），并区分“款式补充”内容；空白和有文字也视为不同款式，原始规格及批次不变。库存按批次显示和操作；使用周期仅参考可确认开封日期的单件核销，多批次同时开封时不估算整款剩余天数。库存流水最多保留 500 条，旧记录或导入的历史可能不完整，使用周期估算仅供参考；无法确认周期时不估算。库存价值按在库数量和单价计算，并非完整的累计支出统计。

日用品未上传图片时，统一使用与其他品类风格一致的暖色手绘插画，录入预览同步使用，不再区分猫砂或牙膏，已上传的实拍不变。已核销卡片的品类统一使用橙色胶囊，品牌使用灰色文字；各批次的编辑、删除收进更多菜单，删除使用危险色并需确认。

每个商品最多保存 6 张照片，可一次多选上传；新照片按比例缩至长边不超过 1024px，并逐步调整 JPEG 质量和尺寸，尽量将图片控制在 150 KB 以内。已有照片不会自动重新压缩。录入表单使用 72px 横向缩略图，点击设为封面并移至首张，也可逐张删除；超限整批不添加并明确提示。列表仍显示正方形封面，多图时显示相机与张数，点图可左右滑动或用圆点切换大图。数据使用 `images` 数组，旧 `imageData`／`image` 单图自动迁移，空数组表示恢复默认插画；补货、归档、JSON 备份均保留全部照片。删除批次会一并移除该批次内嵌照片，其他批次及归档独立保留。设置页显示照片数据量与预计 JSON 备份大小；照片越多，本机存储和备份文件越大。

底部「备份设置」仅用小红点提示本地更改尚未导出 JSON 备份。设置页解释计数是自上次备份以来的本地保存次数，并非错误、待办或独立商品数量；数据仍保存在本机。

## 📂 渐进式模块化目录结构

```text
├── index.html          # 语义化应用主界面与弹窗骨架
├── css/
│   └── styles.css      # 暖米色移动端自适应样式与 iOS 日期选择器兼容层
├── js/
│   ├── covers.js       # 离线压缩分类插画资源包（零外部图片请求）
│   ├── constants.js    # 存储键名、普通食品/营养品/药品三层分类元数据与流水枚举
│   ├── utils.js        # 严格日期校验（防夏令时漂移与非法月日溢出）、克价与规格解析
│   ├── domain.js       # 核心状态、无损 Schema 清洗迁移、分顿扣减、影子归档同步与库存流水引擎
│   ├── storage.js      # IndexedDB 单例连接池 + LocalStorage 时间戳双写同步、备份预校验与恢复快照
│   ├── stats.js        # 食品/营养品/药品分离统计、效期时间轴与品牌深度档案计算
│   ├── modal.js        # 弹窗生命周期、焦点恢复、键盘循环与背景滚动锁定
│   ├── ui.js           # 公共视图协调、每日记录、商品表单与库存流水界面
│   ├── ui-pantry.js    # 库存状态、筛选、数量明细与商品卡片渲染
│   ├── ui-settings.js  # 设置页、备份提醒与本地存储健康状态渲染
│   └── app.js          # 全局事件委托、表单校验与 Service Worker 自动更新注册
├── sw.js               # PWA 离线缓存服务（同源 HTML/CSS/JS 网络优先 + 离线无缝回退）
├── manifest.json       # 主屏幕独立全屏 App 配置文件
├── icon-192.png        # PWA 桌面图标 (192×192)
├── icon-512.png        # PWA 高清启动图标 (512×512)
└── .nojekyll           # 禁用 GitHub Pages Jekyll 构建以加速静态资源发布
```

## 🚀 GitHub Pages 无损升级步骤

1. 打开你的 GitHub 仓库（如 `yoyogipark/meow-pantry`）。
2. 将压缩包内的文件（`index.html`、`sw.js`、`manifest.json`、`css/` 文件夹、`js/` 文件夹及图标文件）上传并覆盖到仓库根目录，点击 **Commit changes**。
3. 等待约 30～60 秒构建完成后，在手机浏览器或桌面图标刷新一次即可平滑升级——**原有手机浏览器内的库存、实拍图与每日记录 100% 自动保留并平滑兼容，无需任何手动迁移！**

## 🧪 本地测试

需要 Node.js 18 或更高版本：

```bash
npm ci
npm test
```

`npm test` 会先检查全部 JavaScript 文件的语法，再运行库存扣减、撤销、备份恢复及界面摘要等一致性测试。

发布前可用一个命令同步提升 Service Worker 与全部 CSS/JS 资源版本：

```bash
npm run version:pwa -- 51
```

版本脚本会同时更新 `index.html` 和 `sw.js`，随后运行 PWA 资源一致性检查。
